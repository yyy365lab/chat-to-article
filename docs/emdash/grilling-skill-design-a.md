## 1文字も書かないうちに、設計が3回壊れました 😇

AI との会話を記事に変えるスキル「chat-to-article」を作りました。中身は Markdown が1枚だけで、書いたコードは0行です。

面白かったのは中身より作り方のほうでした。実装に入る前に、AI に自分を容赦なく問い詰めさせる工程をはさんだんですよ。

そしたら着手する前に設計が3回ひっくり返りました。普通に「記事化スキル作って」と投げていたら、たぶん全部あとから殴られていたやつです 🔥

## できたのは、こういう流れの1枚です 📄

呼び出すと、AI は会話を勝手に読んで「何をやったか」の目次を内部で作り、そのうえで5問だけ聞いてきます。素材集めから記事まで、人間がやるのは5問に答えるところだけです。

その5問がこれ。

```
Q1 何を作った話にしますか？   ➡️ AI が推測した一行を提示
Q2 読者は誰ですか？
Q3 記事の主眼は？
Q4 公開範囲は？
Q5 文体は？
```

つまり全部に推奨案が付いているので、「全部推奨で」の一言で書き始まります。この記事もまさにその一言から出てきました 🙌

実体は SKILL.md が1ファイル、4,000字ほど。スクリプトも外部ファイルもありません。

## 元ネタは 2,015バイトのスキルでした 🤔

きっかけは Matt Pocock の skills リポジトリです。37個も入っているんですが、作者が「変更を加えるときは毎回使え」と書いているのが grilling でした。

実物を開いたら 2,015バイトしかなくてびっくりしました。それでこの評価なので、密度がすごいんですよ。

核はこの一文です。

> フロンティアとは、前提がすでに確定している決定の集合——つまり、まだ聞いていない答えを推測せずに、今この瞬間に聞ける質問のことである。

絵にするとこんな感じ。

```
    「予約機能をつくる」
     ├── 誰が予約できる？   ← 今聞ける
     ├── 重複予約を許す？   ← 今聞ける
     └── 承認フローは？     ← 今聞ける
          └── 承認者は誰？  ← 上が決まるまで聞けない
```

つまり「上の答え次第で消滅する質問」を今ぶつけるのを、構造的に禁止しているわけです 💡

## 崩壊1 — 「作りたいのは記事じゃなくてスキルです」😇

2ラウンド目、AI が「どのコミュニティに出しますか？」と聞いてきました。それっぽいんですが、答えていてなんか変だなと。

で、止めてこう言いました。

> 私がやりたいのは、記事を作る、ということではありません。記事を作るためのスキルを作る、です。

決めることが2層に分かれていたんですね。スキルの仕様(今決めること)と、記事ごとに変わること(読者・主眼・公開範囲)。読者や公開先は完全に後者でした。

スキルに埋め込むべきは答えじゃなくて「聞く仕組み」だった、というわけです。気づかず進めていたら、自分にしか使えないスキルができていました 🤔

## 崩壊2 — 実測したら 34MB でした 📊

「プロジェクト全体の会話ログを素材にする」と決めた直後、AI が勝手に手元のログを数えてきました。

```
プロジェクト A : 9セッション  34MB
プロジェクト B : 1セッション  15MB
プロジェクト C : 0本         ―
```

つまり、文脈に入る量じゃないうえに、そもそもログが1本も残っていないプロジェクトもある、ということです。

ここは grilling の役割分担が効いた場面でした。

> 事実を見つけるのはお前の仕事であり、断じてユーザーの仕事ではない。(中略)決定はユーザーのものである。

自分は「全体を素材に」と思いついただけで、それが何MBかなんて知りません。聞かれても答えられなかったです 😅

## 崩壊3 — 配布物にした瞬間、前提が消えた 💥

3つ目は自分で落としました。「これ配布するので、どの環境でも同じ挙動にしたいです」と。しかも Gemini でスキル化するとプロンプト文しか登録できない。

この一言で、スクリプトもファイル読み取りも個人の履歴データも全部使えなくなりました。設計の土台が丸ごと消えた感じです 😇

そこで、処理の手順は共通にして「素材の在り処」だけを環境で縮退させる形に組み替えました。

1. いまの会話 ← どの環境にも必ずある
2. ユーザーが貼った/添付したログ
3. 読める環境なら、過去のセッションログ

つまり上から順に使えるものを使い、1 だけでも記事は書ける、という設計です。長いチャット1本で作りきったなら、その会話が全体像そのものですからね。

## 使ってみたら、1回目で直すところが出ました ✍️

できあがってすぐ、この会話自体を素材にして走らせました。仕様どおりには動いたんですが、出てきた記事が要件定義書みたいな文章だったんですよ 😅

なので文体の節と、ゆるっと・ていねい・きっちり・実況・さくっと・ハンズオンの6種プリセットを足して、質問を4問から5問にしました。今読んでいるこれが、その「ゆるっと」です。

それから投稿先にした CMS で実測したら、Markdown をテキストのまま貼ると記号が残り、描画済みを貼ると見出しも引用も表もブロックで入る、と分かりました。mermaid は描画されなかったので、図はテキスト図解に統一しています。

数字の裏取りも1つ直しました。「実装は10分」と書いていたんですが、記録に残っているのはラン全体の1時間24分だけ。体感の数字を消して、裏の取れる事実だけで言い直しました。

## 真似するなら、ここからだと思います 💡

一番効いたのは、AI に「今聞ける質問だけ」を出させたことでした。質問が依存関係の順に並ぶので、答える側が迷子にならないんですよ。

そして推奨案が必ず付くので、疲れていても「全部それで」で進められます。ここ、地味ですがかなり大きいです。

自作スキルは今9個あって、うち7個はスクリプトなしの Markdown だけです。スクリプトを持たせるかどうかは、配布するかどうかで決まると思っています 🤔

同じように「スキルは聞いたことあるけど作ったことはない」という方は、作りたいものを1個決めて、着手前に AI に問い詰めさせるところから試してみてください。設計が壊れたらむしろ当たりです 👋

## おわりに 👋

grilling 5ラウンド、設計から実装まで1時間24分。うちほとんどが質問と回答の往復で、実装は終盤のごく一部でした。

作る前に3回壊れたということは、作った後に3回壊れなかったということでもあります。この感覚、けっこうクセになります 🔥
