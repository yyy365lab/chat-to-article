# chat-to-article

AI とのチャットのやり取りから、**コミュニティに投稿する記事**を書き起こすエージェントスキルです。

作ったものを仲間に共有したい。でも記事を書くのは大変。
——その間を、AI との会話で埋めるためのスキルです。会話を放り込むと **6 つだけ質問**が来て、
**投稿先に貼るだけの形**(HTML または Markdown)で記事が出てきます。

```
チャットのやり取り → ①目次化 → ②質問 6 つ(推奨つき) → ③執筆 → ④タイトル 3 案 → ⑤秘匿情報の点検 → ⑥出力
```

## 特徴

- **会話の時系列をなぞりません。** 記事の主役は「作ったもの」と「読者が持ち帰れる知見」で、会話は素材です
- **質問は 6 つだけ。** 全部に推奨案が付くので「全部推奨で」の一言で書き始まります
- **人が書くブログの文体。** 一人称の体験談として、仲間に向けて話す文章にします(仕様書調にはしません)
- **文体は 6 種から選べます。** ゆるっと / ていねい / きっちり / 実況 / さくっと / ハンズオン
- **図解つき。** 仕組み・流れ・分岐は文章より先に図で見せます(HTML なら SVG 画像、Markdown ならテキスト図解か mermaid)
- **タイトルは本文から 3 案生成**(結果型 / 読者の得型 / 一言型)。推奨と理由つき
- **秘匿情報を既定で伏せ字化。** 個人名・社名・パス・トークンを置換し、何を置換したかは記事ではなくチャットで報告します
- **1 ファイル・スクリプトなし。** `SKILL.md` 1 枚で完結するので、Claude Code / Codex / Gemini のどれでも同じ挙動です

## 使い方

作業が一区切りついたところで呼び出します(**明示呼び出し専用**。会話中に勝手に記事を書き始めることはありません)。

```
/chat-to-article
```

すると、会話から「何をやったか」の目次を内部で作ったうえで、次の 6 問が推奨案つきで届きます。

| | 質問 | 選択肢 |
|---|---|---|
| Q1 | 出力形式は？ | (a) HTML ファイル (b) Markdown |
| Q2 | 何を作った話にしますか？ | 素材から推測した一行が提示されます(素材が多いときは「2 本に分ける」も選択肢に) |
| Q3 | 読者は誰ですか？ | (a) 一般の開発者 (b) 特定の技術コミュニティ (c) 社内 |
| Q4 | 記事の主眼は？ | (a) 成果物の紹介 (b) 詰まった所と解決 (c) 得られた学び |
| Q5 | 公開範囲は？ | (a) 一般公開 (b) 限定公開 (c) 社内のみ — 伏せ字の強さが決まります |
| Q6 | 文体は？ | (a) ゆるっと (b) ていねい (c) きっちり (d) 実況 (e) さくっと (f) ハンズオン |

「全部推奨で」と返せば、そのまま執筆に入ります。書き上がると次のものが届きます。

1. **記事本体**(保存先を聞かれます。ファイルに書けない環境ではチャットに丸ごと出ます)
2. **タイトル案 3 つ**と推奨(採用案は記事のタイトルにも入っています)
3. **伏せ字の一覧**と、判断をあなたに返す「グレーゾーン」の申告
4. **投稿先への貼り方**(3〜5 行)

### 素材について

使えるものが上から順に使われます。**1 だけでも記事になります。**

1. いまの会話
2. 貼り付け・添付したログ
3. 過去のセッションログ(ファイルを読める環境のみ。Claude Code なら `~/.claude/projects/` 配下)

### 文体プリセット

| 文体 | こんなとき |
|---|---|
| **ゆるっと** | ふわっとしたコミュニティ向け。口語・絵文字あり・1 段落 2〜3 行・図解多め |
| **ていねい** | です・ます、絵文字なし。落ち着いたブログ |
| **きっちり** | だ・である。Qiita / Zenn など技術メディア向け。表・箇条書き可 |
| **実況** | AI とのやり取りの引用を多めに。その場にいる感じ |
| **さくっと** | 冒頭に TL;DR、1,000〜1,500 字。SNS・社内チャット共有向け |
| **ハンズオン** | 二人称「あなた」。手順番号・コマンド・確認ポイントで読者に再現させる |

## 出力形式と投稿先

Q1 で選びます。投稿先が会話から分かれば、その投稿先向けの形式が推奨されます。

### HTML ファイル(Markdown を解釈しない CMS 向け)

エディタが Markdown の記号を解釈しない CMS(Cloudflare の **EmDash** など、TipTap 系のエディタ)向けです。
記事は自己完結の HTML 1 本で出力され、図は `<img>` の SVG 画像として埋め込まれます。貼り方:

1. HTML ファイルをブラウザで開く(ダブルクリックで可)
2. **Ctrl+A → Ctrl+C**(描画された見た目ごとコピーされます)
3. CMS の投稿画面で本文欄をクリックして **Ctrl+V**
4. タイトルは CMS のタイトル欄に入力(採用案が提示されます)

見出し・引用・コードブロック(言語ラベル付き)・表・図・絵文字が、そのままエディタのブロックになり、
公開後も CMS のテーマで装飾されます(EmDash で実測済み)。HTML のソースをテキストとして貼ると
タグが文字のまま出るので、必ず**描画した画面をコピー**してください。

### Markdown(そのまま貼れる投稿先向け)

Qiita / Zenn / GitHub / note / 社内 Wiki など。投稿先ごとに使ってよい要素(表・mermaid・脚注など)を
切り替えます。投稿先が分からなければ、汎用の Markdown で出ます。

## インストール

### skills.sh(Claude Code / Codex ほか)

```bash
npx skills@latest add yyy365lab/chat-to-article
```

更新は `npx skills update`、削除は `npx skills remove chat-to-article`。

### 手動

`skills/chat-to-article/SKILL.md` を、お使いのエージェントのスキル置き場にコピーします。

- 全プロジェクトで使う: `~/.claude/skills/chat-to-article/SKILL.md`
- 特定プロジェクトのみ: `<プロジェクト>/.claude/skills/chat-to-article/SKILL.md`

### Gemini など、プロンプトしか登録できないツール

`SKILL.md` の中身(frontmatter より下)を**そのまま指示文として登録**してください。
スクリプトも外部参照も持たない 1 ファイル構成なので、貼るだけで同じ挙動になります。
ファイルを書けない環境では、記事は **1 つのコードブロック**にまとまって返ってきます
(チャットの本文と混ざらないように)。コピー用ボタンで全文を取り、HTML なら `.html` として
保存してブラウザで開く(または Canvas のプレビューで描画する)→ 範囲コピー → CMS に貼る、の順です。

## 中身

```
skills/chat-to-article/SKILL.md      スキル本体(これ 1 枚で完結)
docs/handoff-to-paste-route.html     見本: HTML 出力(ゆるっと / SVG 図入り / EmDash 向け)
docs/grilling-skill-design.md        見本: Markdown 出力(ゆるっと)
README.md / LICENSE
```

`docs/` の見本は、どちらも「このスキルを作った過程」をこのスキル自身で記事化したものです。

## 設計方針

- **1 ファイル・スクリプトなし。** どのツールでも同じ挙動にするため。`references/` にも分けません
- **素材の縮退。** 過去ログを読めない環境でも、目の前の会話だけで成立させます
- **答えではなく、聞く仕組みを埋め込む。** 読者・主眼・文体は記事ごとに変わるので、スキルは毎回聞きます
- **貼ってみるまで信じない。** 投稿先の挙動(何が残り、何が消えるか)は実際に貼って確かめた結果を書いています
- **公開は取り消せない。** 迷ったら伏せる、を既定にしています
